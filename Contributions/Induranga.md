# My Contribution

**Name:** K.L.I. Sathsarani  
**Index Number:** D/BSE/24/0027

## My Role

I worked as the **Product Owner (PO)** for the Medication Reminder & Tracker project. My main responsibilities were acting as the direct liaison with the designated Client Team, gathering and clarifying requirements, maintaining and prioritizing the Product Backlog, and defining acceptance criteria for User Stories. In addition to my Product Owner responsibilities, I contributed to the system design by preparing the main architectural and analysis diagrams and supported frontend development by implementing the Caregiver Home and Profile interfaces.

## What I Did

- Acted as the primary point of contact between our development team and the designated Client Team to gather, clarify, and understand project requirements.
- Collected and organized functional requirements from the Software Requirements Specification (SRS) to ensure that the product features aligned with the expected system functionality.
- Created and maintained the Product Backlog by organizing User Stories according to their business value, priority, and planned Sprint allocation.
- Prioritized User Stories to help the team focus on essential features and deliver the core functionality of the Medication Reminder & Tracker application.
- Defined and refined User Stories using the standard format: *As a [persona], I want [capability], so that [benefit]*.
- Prepared acceptance criteria for User Stories to establish clear, testable conditions for determining whether each feature meets the requirements.
- Reviewed User Stories using the INVEST principles to improve their independence, value, clarity, estimability, size, and testability.
- Created the Architecture Diagram to illustrate the overall system structure, major components, and interactions between the Flutter application and Firebase services.
- Designed the Entity-Relationship (ER) Diagram to represent the main data entities, their attributes, and relationships within the system.
- Prepared the Use Case Diagram to identify the system actors and illustrate their interactions with the application's main functionalities.
- Created the User Journey Flow diagrams to illustrate the steps users follow when interacting with the application and navigating through important workflows.
- Contributed to frontend development by implementing the Caregiver Home screen, focusing on presenting caregiver-related information and relevant application features.
- Developed the Caregiver Profile screen to provide a user interface for displaying and accessing caregiver profile information.
- Worked to ensure that the diagrams and frontend interfaces aligned with the requirements and intended functionality of the Medication Reminder & Tracker application.
- Supported the team by communicating requirement clarifications, identifying gaps in the backlog, and helping maintain a shared understanding of the product scope.

## Challenges I Faced

- Gathering and interpreting requirements from the SRS and ensuring that they were translated into clear, valuable User Stories.
- Prioritizing features while balancing essential MVP functionality with additional features planned for later Sprints.
- Defining acceptance criteria that were specific enough to support implementation and testing.
- Ensuring consistency between the requirements, User Stories, architecture, ER diagram, use cases, and user journey flows.
- Designing the architecture and data model to represent the relationships between patients, caregivers, medications, schedules, and medication history.
- Ensuring that the Caregiver Home and Profile interfaces aligned with the expected user experience and the overall application design.
- Balancing Product Owner responsibilities, documentation, system design activities, and frontend development within the planned project timeline.

## Outcome

My contribution helped establish a clear understanding of the product requirements and provided the team with an organized foundation for planning and developing the Medication Reminder & Tracker application. By gathering and clarifying requirements, maintaining and prioritizing the Product Backlog, defining acceptance criteria, and refining User Stories, I supported the team in focusing on user value and the planned Sprint goals.

The architecture, ER, use case, and user journey diagrams helped communicate the system structure, data relationships, functional scope, and expected user interactions. My frontend contributions to the Caregiver Home and Profile screens also supported the development of the application's caregiver-related functionality.

Overall, my work combined Product Ownership, requirements engineering, system analysis and design, and frontend development, contributing to both the planning and implementation of the project.
